## 关键概念（今天新学的）

- 订阅六参数：`chainId, contract, topic0, topic1, topic2, topic3`。`0` / `address(0)` / `REACTIVE_IGNORE` 分别表示链、合约、topic 位的通配。
- **只支持精确相等**；单个订阅内无 OR；至少一项具体；订阅存在节点里不在 storage 里。
- `unsubscribe()` 必须六项**完全一致**，否则静默失败——老订阅还在继续扣钱。
- `LogRecord`：`data` 只有**非 indexed** 参数；`opCode` = topic 数量；`blockHash` / `txHash` 是 `uint256` 不是 `bytes32`。
- ERC-20 `Transfer(address indexed from, address indexed to, uint256 value)`：`opCode = 3`，`data = abi.encode(value)`，`topic1 = from`，`topic2 = to`。
- `topic0 = keccak256("Transfer(address,address,uint256)") = 0xddf252ad…23b3ef`；模板的 `Ping(address,uint256)` 是 `0xfd8d0c1d…dc063c9d`。**两个不能混**。
- 不匹配 / 低于阈值 → **`return`，不能 `revert`**（revert 照样收费）。
- `onlySystem` 防止别人伪造 `LogRecord` 调你的 `react()`。
- 回调 payload 第一个参数必须是 `address(0)` 占位，网络会替换成 Reactive 合约地址；目标链用 `onlyServiceProvider` + `onlyCallbackSender` 两道校验。
- 部署顺序：① 源链事件源 ② Lasna Reactive（订阅 + 充值）③ 目标链 Callback（带 ETH）④ `setRecipient` ⑤ 触发。

## 卡在哪 / 怎么解的（真实排错记录）

**坑 1：`forge script --broadcast` 三次部署交易全失败（status 0，gasUsed 等于 gasLimit）。**
- 排查：`cast receipt` 看 status=0；`cast tx` 看 gasLimit 只有 123155；但 `cast estimate --create <bytecode>` 返回 **508564**。`publicnode` 的 gas 估算偏低，Foundry 照单全收 → 部署交易 OOG。
- 解决：改用 `cast send --create` 并**显式给 gasLimit**（部署源链 800000、Reactive 1500000、Callback 4000000，各自乘 2 倍余量）。全部 status=0x1。
- 教训：公开 RPC 的 `eth_estimateGas` 不一定可信，部署类交易要自己核对 `cast estimate`。

**坑 2：第一次部署的 Reactive 用了 Transfer 的 topic0，但源链合约发的是 Ping → 订阅不匹配，`lastReactBlock` 一直是 0。**
- 排查：`cast logs` 确认源链 Ping 事件存在；检查构造参数发现 topic0 填成了 `0xddf252ad…`（Transfer）而事件是 `0xfd8d0c1d…`（Ping）。
- 解决：按精确相等规则，用正确 topic0 重新部署 Reactive + 重新部署 Callback（Callback 绑定了旧 Reactive 地址）+ 重新 `setRecipient` + 重新触发。
- 教训：订阅是精确匹配——**topic0 填错不会报错，只会什么都没发生**。
