# D1｜为什么需要 Reactive（中文精讲）

> 对应官方原文：<https://dev.reactive.network/reactive-contracts>、<https://blog.reactive.network/reactive-circuit-incentive-program-for-working-integrations/>
> 今天只要回答一个问题：**什么情况下该用 Reactive，什么情况下纯属自找麻烦。**

---

## 一、它到底替掉了哪一坨东西

过去想做「价格跌破就止损」这类自动化，标准做法是：

```
链下 bot：定时轮询 RPC → 判断条件 → 用热钱包私钥签名发交易
```

这套东西的代价：服务器 7×24 要活着、掉线就漏单、私钥放服务器上等于随身携带风险、每次轮询都花钱还不一定准。

Reactive 把「监听 + 判断」搬到了链上：

```
源链合约 emit 事件 → Reactive 合约 react() 被系统自动调用 → 条件满足就发回调 → 目标链合约执行
```

**你只写一个合约，不跑任何后台服务。** 这是它唯一但足够大的卖点。

## 二、它为什么能「自动」——最小心智模型

三句话：

1. 你在**构造函数里订阅**（哪个 chainId、哪个合约地址、哪个 topic0、哪个 indexed 参数）。
2. 匹配的事件发生后，Reactive 网络的**系统合约**替你调用 `react(LogRecord)`——**不是你调的，也不是任何人调的**，所以 `react()` 必须加 `onlySystem`。
3. `react()` 里判断通过，就 `requestCallbackV_1_0` 请求一笔回调，由目标链上的 Callback Proxy 打给你的回调合约。

所以 Reactive 合约本质上是一个**常驻的、按事件触发的状态机**，不是被用户点击的 dApp 合约。

## 三、该用 / 不该用（这张表决定你 D6 的选题成不成立）

| 该用 Reactive | 不该用 Reactive |
|---|---|
| 触发条件是**链上已经发生的事实**（Transfer、Sync、Approval、Cron） | 条件依赖**链下数据**（CEX 价格、API、模型推理）——需要先有人把数据搬上链 |
| 动作是「在另一条链上发交易」 | 动作必须在同一笔交易里原子完成（两链回调是两笔独立交易，**不保证原子**） |
| 可以容忍**秒级延迟**（Reactive 约 1 秒出块） | 需要毫秒级抢跑（专业 MEV bot 的战场，别去） |
| 希望**没有服务器、没有私钥托管** | 高频触发、每次都付费的场景（K 固定 10 万 gas 底噪 × 几千次 = 烧钱） |

最后一条最容易被忽略：**「能不能做」和「值不值得做」是两件事**。D6 选题时如果答不上「为什么必须用 Reactive 而不是一个 cron 脚本」，评委第一个问题就会问这个。

## 四、Reactive Circuit 是什么（了解一下就够）

Reactive 的激励计划：**把 Reactive 真正集成进可用产品**的项目可以申请奖励，评的是「是否形成有效集成」而不是「代码多花哨」。对我们的意义只有一个——**Integration 这个维度从第一天就要想清楚**：Reactive 在你的项目里必须是承担实际功能的一环，不能是摆设。D14 评审四项里有它，赛道 1 要求说明「为什么需要速度」、赛道 3 要求说明「AI 如何参与运行」，本质都是同一件事。

## 五、今天的任务：用例拆解卡

把三个想法按同一个模板拆开，**填不满就说明这个想法还没想清楚**：

| 用例 | 听什么事件（源链） | react() 判断什么 | 回调做什么（目标链） | 为什么不用链下 bot |
|---|---|---|---|---|
| 巨鲸大额转账监控 | Sepolia 上某 ERC-20 的 `Transfer`，value > 阈值 | value 超 10,000 且 1 小时内累计超 50,000 | 回调合约 emit `Alert` 事件，链下脚本推 Telegram | 不用管服务器存活；监控逻辑公开可验证 |
| 钱包异常转出保护 | `Transfer` 且 topic1 = 我的地址 | 单笔 > 总资产 30% | Guardian 把剩余代币转冷钱包 | 私钥不放服务器；条件在链上执行 |
| 价格到点止损 | Uniswap V2 池子 `Sync` | 用储备算价 < 止损价 | 授权代币卖出，设最低成交量 | 不用 7×24 盯盘 |

> 这三条只是示范，你要拆的是**你自己真会用**的东西。D6 的方向卡就是从这里长出来的，现在偷懒，周末就得重做。

## 六、自测

1. 为什么 `react()` 要加 `onlySystem`？不加会怎样？
2. 一个「CEX 价格跌破 3000 就卖出」的需求，能不能直接用 Reactive 做？
3. Reactive 合约和普通 dApp 合约最大的区别是什么？

<details>
<summary>答案</summary>

1. 因为 `react()` 只能由系统合约调用；不加的话任何人都能直接调你的 `react()` 伪造触发条件，等于把风控开关交给攻击者。
2. 不能直接用。CEX 价格是链下数据，得先有 oracle 或有人把价格写进链上事件，Reactive 才能订阅。
3. 它不被用户点击触发，而是被「匹配到的链上事件」触发；它是常驻状态机，且要自己养余额（见 D2）。
