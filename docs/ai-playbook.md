# AI 协作手册：这两周我怎么配合你学

写给未来的自己看：这套共学最大的风险不是「学不会」，而是**每天 1–1.5 小时被环境问题和旧写法资料耗光**。AI 的价值就在这两件事上——省掉检索和排错的时间，把时间留给「想清楚事件 → 条件 → 动作」。

## 一、分工原则

| 我该做 | 我不该做 |
|---|---|
| 讲清概念、给最小可跑示例、解释报错 | 替你决定项目做什么（选题得你自己真会用） |
| 按 Omni 写法审代码、挑出旧写法残留 | 代你写完整项目然后你「看不懂但能跑」 |
| 帮你把当天的对话压缩成打卡笔记 | 编造交易哈希、合约地址、跑通结果 |
| 写/审测试、部署脚本、README、提交包清单 | 接触任何私钥、助记词、助手的 `.env` |
| 追进度：今天该做什么、欠了几个任务 | 替你向助教提问（技术上你得自己过一遍） |

一句话：**我负责让你少卡 80% 的机械时间，你负责那 20% 真正长本事的判断。**

## 二、每日循环（约 60–90 分钟）

```
① 预习 5 min   我给你讲今天的 3 个核心概念 + 一个反例（什么写法是错的）
② 定计划 5 min 把今天的任务拆成 3–5 个可验证的小步，先写 notes 里的「今日计划」
③ 动手 30–45m  我提供最小示例 / 骨架，你在本地跑；报错直接贴给我
④ 收口 10 min  跑通就记交易哈希；没跑通就写「卡在哪 + 排查了什么」
⑤ 打卡 5 min   我按 notes/ 模板生成当天 md，你改两句主观感受后贴到 WCB
```

**每天开始时的一句开场（直接复制给我）：**
> 今天是 D{n}（{日期}），主题「{主题}」。先给我 3 分钟版概念讲解 + 一个错误写法示范，然后带我拆今天的任务。我的环境：Foundry 已装 / 已有 lREACT {数量}。

## 三、分阶段我能帮上什么

| 阶段 | 我会主动做 | 你只需要 |
|---|---|---|
| 准备（第 0 周） | 校对 Foundry / cast 安装；算 faucet 该换多少 lREACT；把仓库骨架和 `.gitignore` 建好 | 建钱包、领币、跑命令 |
| 第 1 周 D1–D2 | 画「源链 → Reactive → 目标链」时序图；用一张表讲清 `balance / reserves / debt`；出 5 道自测题 | 读懂，答题，纠正我的说法 |
| D3–D5（写代码） | 给 Xfers / Callback / Cron 三个最小可跑骨架（Omni 写法），逐行讲；你贴报错我定位 | 部署、充值、在浏览器上确认 `react()` 被调用 |
| D6 选题 | 当「评审」用四项标准拷问你的一句话方向卡；给出「这个选题不需要 Reactive」的反驳，逼你说清必要性 | 定方向卡、DoraHacks 报名 |
| 第 2 周 D8–D9 | 帮你把方向卡翻成三段时序图；review 合约的订阅匹配、幂等、额度上限 | 跑通真实三笔交易 |
| D10–D11 | 列「攻击面清单」（谁能调你的回调、重复执行、金额失控）；写 Foundry 测试用例（正常 + 应被拦） | 判断哪些坑真会发生在你项目上 |
| D12–D13 | 部署脚本一键化；按评审四维体检 README；生成提交包 checklist；延迟实测脚本 | 录 Demo 视频、正式提交 |
| D14–冲刺 | 扮演评委提 5 个刁钻问题；对着 Demo 脚本压时间 | 讲 3 分钟、答 2 分钟 |

## 四、可复制的 prompt 模板

**① 概念精讲（D1/D2/D5 这类概念日）**
> 用 Reactive Omni 新写法讲解「{概念}」。要求：① 一句话定义 ② 一个链上具体例子 ③ 一个常见错误理解并纠正 ④ 3 道自测题（先别给答案）。

**② 代码审稿（每次写完合约都过一遍）**
> 按 Omni 写法审这段合约，逐条检查：`vm` 修饰符 / ReactVM / `emit Callback` / 系统合约地址误用 / `react()` 是否 `onlySystem` / 回调用 `requestCallbackV_1_0` / 回调首参是否 `address` / 是否 `onlyServiceProvider` + `onlyCallbackSender` / 订阅是否过宽导致费用失控 / 是否幂等 / 金额是否有上限。只报问题不重写。

**③ 部署报错排查**
> 这段报错发生在 `forge script ... --broadcast`（链：{Lasna/Sepolia}）。给我 ① 最可能的 3 个原因排序 ② 每个原因一条验证命令 ③ 最小修复。不要猜，先说怎么验证。

**④ 写测试（D11）**
> 给这个合约写 Foundry 测试：一个正常触发、一个应该被拦下（{冒充回调/重复执行/超额度}）。要求用 `vm.prank` 模拟 System 与攻击者，并说明每个断言在验证什么。

**⑤ 选题压力测试（D6）**
> 这是我的一句话方向卡：「{监听 X，当 Y 时在 Z 链做 W}」。请按 Execution / Integration / Usefulness / Craft 四项各打 1–5 分并说明理由，然后给我三个「这个项目其实不需要 Reactive」的反驳，我逐条回应。

**⑥ 提交包体检（D13）**
> 按官方提交要求逐项核对我的仓库：公开仓库 / 合约地址 / 三段交易哈希可核验 / <3 分钟视频 / README 能否让陌生人复现 / 是否写明 AI 生成部分。缺一项列一项，别给好评。

## 五、把上下文固化进仓库（省掉每天重复贴）

本仓库根目录的 `AGENTS.md` 就是给编程工具读的：Claude Code、Codex 会自动读 `AGENTS.md`，Cursor 读 `.cursor/rules` 或 `AGENTS.md`。**每次开新会话先确认它被读到**，能挡掉一大半「AI 给我写旧写法」的问题。

## 六、红线（我自己也要守住）

1. 不向任何工具/人提供私钥、助记词；`.env` 永不入库（已 gitignore）。
2. AI 生成代码必须在 README 里声明范围与验证方式（D12 明确要求）。
3. 交易哈希、延迟数据只能来自真实链上执行，**不许编**。没跑通就写「未跑通 + 卡在哪」。
4. 参考 `main` 分支老 demo 只能取思路，代码必须改写成 Omni 写法。
5. 打卡笔记是公开的：不写密钥、不写内网地址、不写他人隐私。

## 七、进度自检（每天 10 秒）

- [ ] 今天的 `notes/YYYY-MM-DD.md` 有「做了什么 / 卡在哪 / 交易哈希」三块实质内容
- [ ] 核心任务已完成数 ≥ 已过天数 × 0.8（结业要 12 个里拿 ≥600 分，约完成一半多一点）
- [ ] 「跨链回调三步走」（D4）和「跑通你的项目」（D9）两个必做任务有没有动
- [ ] 本周的 Online Session 回放看了没（有回放，可以补）
